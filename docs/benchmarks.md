## Observations

Counted from the position-error tables below (pooled mean error, each table under its own protocol). A count treats any difference as a win, however small; the tables give the magnitudes.

- WKNN (k=5) with the positive representation has a lower mean error than with the -104 dBm fill on 7 of 15 tables.
- WKNN (k=5) with the exponential representation has a lower mean error than with the -104 dBm fill on 12 of 15 tables.
- WKNN (k=5) with the powed representation has a lower mean error than with the -104 dBm fill on 10 of 15 tables.
- The median ensemble of WKNN, random forest and Horus beats all three of its members on 11 of 19 tables.
- The median ensemble of WKNN, random forest and extra trees (CSI tables) beats all three of its members on 1 of 4 tables.
- Horus has a lower mean error than WKNN on 3 of 19 tables.
- Horus on the raw readings (NaN = not heard, the input its detection model is made for) has a lower mean error than Horus after the -104 dBm fill on 13 of 15 tables, and than WKNN on 8 of 15.
- Methods that do not beat the training-centroid baseline (a mean error at least as large):
  - [ibeacon_rssi / official-geo](#ibeacon-rssi-official-geo): 1-NN; Horus; GP radio map; 1-NN (positive); Horus (raw RSSI, NaN = not heard)
  - [ble_indoor / official-lab](#ble-indoor-official-lab): path-loss ML, known receivers (raw RSSI, NaN = not heard); path-loss ML, receivers estimated (raw RSSI, NaN = not heard)
  - [csi_fingerprint / points-lab](#csi-fingerprint-points-lab): 1-NN; k-NN (k=5); WKNN (k=5); Horus; ensemble: median of WKNN, RF, Horus; MLP; SVM (RBF); GP radio map

## Setup

- Hardware: 13th Gen Intel(R) Core(TM) i9-13900K, 32 logical CPUs, 39.2 GB RAM; Linux-6.6.114.1-microsoft-standard-WSL2-x86_64-with-glibc2.43. The workstation was shared (a GPU training job and other development processes ran at the same time), so times are indicative; every cell ran on the CPU only.
- Threads: OpenBLAS / OpenMP / MKL = 8 (PyTorch takes its intra-op threads from OMP_NUM_THREADS); forests `n_jobs=8`. One cell at a time.
- Software: Python 3.14.4, numpy 2.4.5 (scipy-openblas 0.3.31.188.0), pandas 3.0.3, scipy 1.17.1, sklearn 1.8.0, torch 2.11.0+cu128; indoorloc 0.2.0.dev0.
- Code: each cell records the source digest of the library it imported (sha256 over the package's .py/.json files). The finished cells ran 3 versions: `84a6dc45715c3b84` (328 cells): a copy frozen with `run.py --freeze` at 2026-09-28 10:04 UTC from git commit `ff90d76a9dd9` on `refactor/five-layer-architecture` with uncommitted changes; `34d0d1b7013ddf9b` (16 cells): a copy frozen with `run.py --freeze` at 2026-09-29 01:00 UTC from git commit `ff90d76a9dd9` on `refactor/five-layer-architecture` with uncommitted changes; `ea8891eee6b1a6da` (3 cells): a copy frozen with `run.py --freeze` at 2026-09-28 14:19 UTC from git commit `ff90d76a9dd9` on `refactor/five-layer-architecture` with uncommitted changes.
- Limits per cell: 30 minutes and 2,500 MB resident memory; a cell that exceeds either is killed and reported as such (never dropped).
- Cost of the recorded runs: 349 cells (347 finished, 2 stopped at a limit, 0 failed), 2.2 h of wall time in all and 6.2 h of CPU time; largest peak of a finished cell 2,290 MB. Superseded runs of a cell (reruns, and attempts repeated after memory throttling) are not counted.
- Timing: *Fit s* and *Predict s* are the command line's own timers around `fit` and `localize` (preprocessing included), summed over folds. *Peak MB* is the maximum resident memory of the cell's process (`ru_maxrss`), i.e. Python, imports and the loaded dataset included.
- Memory throttling: the cells ran inside a Linux control group shared with other processes (memory.high 4,096 MB, memory.max 6,144 MB, swap 4,096 MB). Above memory.high the kernel slows every allocation down, which stretches wall times without changing any result. Each cell records the group's memory-pressure stall during the cell (`memory_stall_s`, Linux PSI) and its own CPU time; times marked † come from cells during which some task of the group waited for memory for more than 10% of the cell's wall time (PSI `some`, the stricter of the two totals; 0 of 347 finished cells).
- Seeds: 0 for every protocol and seeded method; `PYTHONHASHSEED=0`.
- Reproducibility: 124 cells were run twice in separate processes (the second run replaced the first and recorded `rerun_check`); largest difference over all their pooled and per-fold metrics: 0 (identical).
- Determinism check: 82 cells were run again with `run.py --verify` (2026-09-29, library source digest `34d0d1b7013ddf9b`, `ea8891eee6b1a6da`, a later version of the code than the one the cells recorded: the check also shows that the changes made since leave these numbers unchanged); largest difference over all their pooled and per-fold metrics: 0 (identical).

Readings in whole or averaged dBm make exact distance ties common. The library and the numpy recomputation order equal distances by training index; scikit-learn 1.8.0's brute-force search does not, and gets slightly different means where test rows tie at the k-th neighbour (UJIIndoorLoc k-NN (k=5): 19 test rows, 8.8314; UJIIndoorLoc WKNN (k=5): 19 test rows, 8.8166; BBIL office WKNN (k=5), fill -110 dBm: 34 test rows, 3.5183).

The BBIL reference value was obtained with missing readings set to -110 dBm, below the weakest training reading (-106 dBm); with the library's default fill of -104 dBm the same WKNN gives 3.5173 m (table below). Only the 2,192 training scans that miss a receiver are affected; the test scans miss none.

## Methods and preprocessing

Specs exactly as passed to `--method` / `--preprocess`; every parameter not shown is the library default, and each result file stores the fully resolved parameters (`model_params`).

| Method | spec | notes |
| :--- | :--- | :--- |
| training centroid (baseline) | `benchmarks.baselines:TrainingCentroid` | benchmarks/baselines.py: mean training position, majority floor/building |
| 1-NN | `knn(k=1)` | Bahl & Padmanabhan, RADAR, INFOCOM 2000; equal distances ordered by training index |
| k-NN (k=5) | `knn` | k-NN, uniform weights, floor/building by vote |
| WKNN (k=5) | `wknn` | inverse-distance weights, floor/building by weighted vote |
| Horus | `horus` | Youssef & Agrawala, MobiSys 2005: Gaussian per location and AP, centre of mass of the 3 most likely locations (see the class docstring for the missing-AP model) |
| random forest | `rf(n_jobs=8)` | Breiman 2001; 100 trees, max_features='sqrt', bootstrap |
| extra trees | `extratrees(n_jobs=8)` | Geurts et al. 2006; 100 trees, max_features='sqrt', no bootstrap |
| ensemble: median of WKNN, RF, Horus | `ensemble(localizers=["wknn","rf","horus"],combine="median")` | coordinate-wise median of the three estimates, label vote; members built from the registry with default parameters (forest predictions do not depend on n_jobs, but the member forests run single-threaded, so the ensemble's times are not the sum of the rows above) |
| ensemble: median of WKNN, RF, extra trees | `ensemble(localizers=["wknn","rf","extratrees"],combine="median")` | as above; used on CSI tables, where Horus is not run |
| MLP | `mlp` | 512-256-128, ReLU, BatchNorm, dropout 0.3, standardized inputs; AdamW (lr 1e-3, weight decay 1e-4), batch 256, at most 100 epochs, early stopping (patience 10) on a 10 % split of the training data; CPU |
| SVM (RBF) | `svm` | one RBF epsilon-SVR per axis (C=1, epsilon=0.01 in standardized units), SVC for labels |
| GP radio map | `gp_radiomap` | Ferris et al., RSS 2006; per-AP hyper-parameters on a 16 x 9 grid; most likely training position |
| GP radio map, per floor | `hierarchical(position_model=gp_radiomap)` | building and floor by k-NN vote, then one GP radio map per floor |
| path-loss ML, known receivers | `pathloss(anchors={anchors})` | log-distance model fitted per receiver, maximum-likelihood position |
| path-loss ML, receivers estimated | `pathloss` | receiver positions estimated jointly with the model from the labelled training scans |
| weighted centroid, known receivers | `centroid(anchors={anchors})` | centroid of the receivers weighted by linear received power (weighted centroid localization, Blumenthal et al. 2007) |

| Preprocessing | spec | notes |
| :--- | :--- | :--- |
| fill -104 dBm | `fill` | FillMissing(value=-104): a missing reading becomes -104 dBm (UJIIndoorLoc's weakest reading) |
| positive / exponential / powed | `positive` / `exponential` / `powed` | Torres-Sospedra et al., Expert Syst. Appl. 42(23), 2015; min = lowest training reading - 1 dBm; α=24, β=e |
| \|CSI\| (linear) | `CSIAmplitude` | \|H\| of every antenna and subcarrier, flattened |
| dB amplitude, NaN → -15 dB | `fill(value=-15)` | csi_fingerprint only: its zero amplitudes (NaN in dB) |
| fill -110 dBm | `fill(value=-110)` | BBIL office only: the setting of the reference value (see the cross-checks) |
| raw RSSI, NaN = not heard | `none` | raw values; missing readings stay NaN (not heard): Horus, whose detection model scores them, and the model-based methods |

## Reproducing

The datasets are read from `$INDOORLOC_DATA` (default `~/.cache/indoorloc/datasets`); `indoorloc info <dataset>` shows the files and their sha256. See [benchmarks/README.md](../benchmarks/README.md).

```bash
python benchmarks/run.py                          # whole matrix, then these documents
python benchmarks/run.py --dataset tuji1          # one dataset
python benchmarks/run.py --dataset sodindoorloc --table official-HCXY   # one table
python benchmarks/run.py --list                   # every cell's command
python benchmarks/run.py --dataset tuji1 --verify # rerun, compare with the stored numbers
python -m benchmarks.crosscheck                   # recompute the cross-checks outside the library
indoorloc benchmark --dataset tuji1 --protocol official --preprocess positive --method 'knn(k=1)'
```
